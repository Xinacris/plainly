# Amazon rebuild: analysis

**Proposed thesis: "Amazon without the noise."** Search results ranked honestly, with no sponsored slots and no badges. The facts you need before buying (price, delivery, returns, warranty) shown up front. Comparing products on one screen instead of across tabs. Amazon's fast checkout stays, and the site works in dark mode. Every proposal below either serves this thesis or keeps the purchase loop working.

I checked the data source live. DummyJSON has **194 products in 24 categories**. Each product has `returnPolicy`, `shippingInformation`, `warrantyInformation`, `availabilityStatus`, `stock`, `brand`, `discountPercentage`, `rating` and **exactly 3 reviews**, and the reviews are generic ("Very satisfied!"). Two things follow from that:
- **Load the whole catalog once and do search, filters and sort in the browser.** That makes filtering instant and gives you facets the API doesn't have. This still uses DummyJSON as you asked.
- **Some fields shouldn't be shown.** For example, `minimumOrderQuantity` is 48 for a mascara, which would look broken.

## 1. Core flows and data model

| Flow | What Amazon does | Entities |
|---|---|---|
| Home | A wall of carousels, deals and personalized rows | Product, Category |
| Search & filters | Query, category scope, sidebar filters, sort, sponsored results mixed in | Product, Facet (brand, price, rating, stock) |
| Product page | Gallery, buy box, variants, bullet points, long description, Q&A, reviews | Product, Review |
| Cart | Line items, quantities, save for later, subtotal | CartItem {productId, qty, price snapshot} |
| Checkout | Address, then delivery option, then payment, then place order | Address, Order |
| Orders & returns | Order history, tracking, return or replace flow | Order {id, items snapshot, total, placedAt, eta, status}, Return {orderId, itemId, reason, status} |
| Account | Sign-in, addresses, payment methods, Prime, lists | User, Address |

**Where the data lives:**
- **DummyJSON:** Product, Category and Review.
- **localStorage:** CartItem, Order, Return and Address.
- **Price snapshots:** orders keep a copy of prices at purchase time, so past orders don't change if the catalog does.

## 2. Pain points

**From your notes:**
1. Sponsored results push the real results down.
2. The badges aren't trustworthy.
3. Product pages are very long, and returns and shipping info are buried in them.
4. Comparing products means juggling tabs.
5. The header and footer are full of links nobody uses.
6. There's no dark mode.

**Ones I'd add:**
7. **Ratings are hard to judge.** A 4.3 average hides how the stars are spread.
8. **Filters are hidden on mobile.** The sidebar is long, and it's hard to see or undo which filters are applied.
9. **Returns are hard to reach.** You have to go through Orders, and the product's return policy isn't shown when you start one.
10. **Delivery estimates are vague** in search results. You only see a firm date inside the buy box.
11. **Checkout has upsells.** Amazon's checkout is fast, as you noted, but Prime and upgrade prompts get in the way.

## 5. Stack and deployment

- **Framework:** Vite, React and TypeScript, with React Router for pages.
- **Data fetching:** TanStack Query to fetch and cache the catalog.
- **Cart and orders:** Zustand with its `persist` middleware, which saves them to localStorage.
- **Styling:** Tailwind, with colors as CSS variables so dark mode is just a set of tokens.
- **Hosting:** Vercel, with a rewrite in `vercel.json` so refreshing a deep link like `/product/12` works. The site is public and needs no sign-in.

I'd skip Next.js: server-side rendering doesn't buy you anything with a public mock API and a 24-hour window.
